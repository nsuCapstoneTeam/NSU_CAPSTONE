## 현재 공식 Workflow

```text
Slack #dev Thread 팀 논의
        ↓
@Claude 논의 요약 / 문서 초안 / 설계 검토
        ↓
사람이 요구사항 확정
        ↓
@Linear Issue / Acceptance Criteria / 담당자 / 우선순위 / 일정 반영
        ↓
최신 main에서 작업 Branch 생성
        ↓
Linear 확정 내용을 기준으로 필요한 GitHub docs/ / ADR / API 문서 갱신
        ↓
AI Agent 또는 Human 구현
        ↓
GitHub PR
        ↓
CodeRabbit 자동 PR Review
        ↓
Human Review
- Linear 요구사항 / Acceptance Criteria
- 코드 / 테스트 / 보안 / 예외처리
- README / docs/ / ADR 정합성
        ↓
작성자 외 팀원 1명 이상 승인
        ↓
사람이 Squash Merge
        ↓
@Linear 상태 정리
```

- [x] Review Profile이 `CHILL`인 것을 확인했다.
- [x] 실제 변경 파일을 CodeRabbit이 Review 대상으로 인식하는 것을 확인했다.
- [x] 무료 OSS Review 제한에 걸리면 자동 Trigger는 되지만 실제 리뷰가 지연될 수 있음을 확인했다.
- [x] 초기에는 CodeRabbit 자체를 Required Check / Merge Gate로 사용하지 않는다.
- [ ] 실제 기능 PR이 생긴 뒤 리뷰 품질과 노이즈를 추가로 확인한다.
- [ ] 실제 FE/BE 코드가 생긴 뒤 필요한 경우에만 Path Instructions를 추가한다.
