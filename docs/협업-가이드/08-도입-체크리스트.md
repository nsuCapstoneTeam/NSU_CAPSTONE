# 도입 체크리스트

← [가이드 목차](README.md)

이 목록은 실제 적용 상태를 추적하기 위한 것이다. 문서 작성이나 설정 저장만으로 실제 동작 검증까지 완료했다고 체크하지 않는다.

## 완료

- [x] 저장소를 `nsuCapstoneTeam/NSU_CAPSTONE` Organization 저장소로 이전했다.
- [x] GitHub `docs/`를 확정 요구사항·정책·설계 문서의 Source of Truth로 정했다.
- [x] Linear는 이슈·담당자·우선순위·일정·상태 관리에만 사용하기로 정했다.
- [x] Linear 상태는 `ToDo` / `In Progress` / `Done`만 사용하기로 정했다.
- [x] Linear ↔ GitHub Issues Two-way Sync를 설정했다.
- [x] Linear 이슈 생성 시 동일한 GitHub Issue가 생성되는지 검증했다.
- [x] GitHub Issue를 닫으면 Linear 이슈가 `Done`으로 동기화되는지 검증했다.
- [x] PR Open → Linear `In Progress`, PR Merge → Linear `Done` 자동화를 설정했다.
- [x] 커밋 Footer는 `Refs` 참조 전용으로 사용하고 이슈 종료 자동화는 PR 본문으로 통일했다.
- [x] 여러 PR이 하나의 이슈에 연결될 때 중간 PR은 `Refs`, Acceptance Criteria를 최종 완료하는 PR만 `Fixes` / `Closes`를 사용하는 규칙을 정했다.
- [x] Human Review에서 Requirement/Issue / Code / Documentation 3종을 확인하는 규칙을 정했다.
- [x] Squash Merge만 사용하도록 저장소 병합 방식을 정했다.

## CodeRabbit PR Review 검증

- [x] `NSU_CAPSTONE` PR에서 CodeRabbit Bot이 자동으로 Review를 시작하는 것을 확인했다.
- [x] PR #3 실행 설정에서 Review Profile이 `CHILL`인 것을 확인했다.
- [ ] Incremental Review가 추가 push 이후 기대한 방식으로 동작하는지 최종 확인한다.
- [ ] CodeRabbit 최종 리뷰 결과와 지적의 품질/노이즈를 확인한다.
- [ ] 초기에는 CodeRabbit 자체를 Required Check로 사용하지 않는 것을 확인한다.

## PR / Issue 자동화 검증

- [x] PR Open → Linear `In Progress` 자동화를 설정했다.
- [x] PR Merge → Linear `Done` 자동화를 설정했다.
- [ ] 실제 일반 PR Open 시 연결된 Linear 이슈가 `In Progress`로 전환되는지 검증한다.
- [ ] 실제 PR Squash Merge 시 Linear `Done`으로 전환되는지 검증한다.
- [ ] 마지막 완료 PR의 `Closes #번호`로 GitHub Issue가 `Closed`가 되는지 검증한다.
- [ ] Linear / GitHub Issue의 최종 상태가 서로 일치하는지 검증한다.
- [ ] 하나의 이슈에 여러 PR을 연결한 경우 중간 PR의 `Refs`가 이슈를 닫지 않는지 검증한다.
- [ ] 자동화가 기대대로 동작하지 않으면 GitHub Integration, PR의 Linear 키, PR 본문의 magic word, Two-way Sync mapping을 확인하고 결과를 기록한다.

위 항목이 완료되기 전에는 `PR Merge → Linear Done → GitHub Issue Closed`를 **설정된 목표 흐름**으로 표현하고, 실제 검증이 끝난 운영 동작으로 단정하지 않는다.

## GitHub Actions / Ruleset

- [ ] 실제 Backend/Frontend 프로젝트 구조가 들어온 뒤 GitHub Actions CI를 구성한다.
- [ ] 정상 코드 성공과 의도적 실패를 샘플 PR에서 모두 확인한다.
- [ ] GitHub에 표시된 실제 check 이름을 기록한다.
- [ ] 문서-only / FE-only / BE-only PR에서 검사가 Pending으로 멈추지 않는지 확인한다.
- [ ] 검증된 CI check를 `main` Ruleset의 Required Status Check로 등록한다.
- [ ] `main` Ruleset에서 PR 필수, 사람 승인 1명, conversation resolution, force push/삭제 금지를 적용한다.

## 팀원 합류 전 마무리

- [ ] `.gitmessage.txt`를 저장소에 추가하고 Footer가 `Refs` 참조 전용인지 확인한다.
- [ ] Linear의 기존 문서 리소스를 GitHub `docs/` 기준에 맞게 정리한다.
- [ ] 모든 자동화/보호 설정 검증이 끝난 뒤 Organization에 팀원을 초대한다.
- [ ] 팀원과 실제 PR 하나를 작성해 CodeRabbit → Human Review → Squash Merge → 이슈 상태 확인 → 브랜치 삭제까지 수행한다.
