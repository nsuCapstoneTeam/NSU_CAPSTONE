# 병합 이후 정리와 되돌리기

← [가이드 목차](README.md)

## 다음 작업 준비

GitHub에서 해당 PR이 실제로 병합되었는지 확인한다. 브랜치에 병합 이후 추가한 미반영 작업이 없는지도 확인한다.

```bash
git status # 현재 변경을 보존했고 작업 상태가 깨끗한지 확인한다.
git switch main # 다음 작업의 기준 브랜치로 이동한다.
git pull origin main # 병합 결과가 포함된 최신 main을 가져온다.
git fetch --prune origin # 원격에서 삭제된 브랜치의 추적 정보를 정리한다.
```

원격 브랜치 자동 삭제나 `fetch --prune`은 로컬 작업 브랜치를 삭제하지 않는다. 로컬 브랜치를 정리할 때는 병합 여부와 남은 작업을 확인한 뒤 다음 명령을 사용할 수 있다.

```bash
git branch -d feat/DEV-123-user-signup # 확인한 작업 브랜치의 일반 삭제를 시도한다.
```

Squash Merge는 원래 작업 브랜치의 커밋을 그대로 연결하지 않으므로 `-d`가 미병합 상태로 판단해 거부할 수 있다. 거부되었다는 이유만으로 `-D`를 실행하지 않는다. PR 병합 결과와 미반영 변경을 확인하기 전에는 브랜치를 보관해 둔다. 다음 작업에 병합된 브랜치를 재사용하지 않는다. [브랜치 삭제][G10] · [Squash 이후 브랜치][G2]

## 병합한 변경 되돌리기

새 작업 브랜치에서 해당 Squash 커밋을 `git revert`하고 다시 PR·검증·사람 리뷰를 거친다. 공개된 `main` 이력을 강제 push로 다시 쓰지 않는다. `revert`는 기존 기록을 유지하며 변경을 취소하는 새 커밋을 만든다. [revert][G11]

아래 예시는 최신 `main`에서 시작한다. 먼저 실제로 되돌릴 Squash 커밋의 SHA를 확인한다.

```bash
git switch -c fix/DEV-200-revert-signup # 실제 복구 작업의 이슈와 이름으로 브랜치를 만든다.
git revert '실제_SQUASH_커밋_SHA' # 예시를 확인한 커밋 SHA로 바꿔 변경을 되돌린다.
```

충돌이 나면 해결 또는 중단 여부를 판단하고 다음 단계로 진행하지 않는다. 최종 메시지도 팀 규칙에 맞게 편집한 뒤 필요한 검증을 수행하고 push·PR을 진행한다. DB 마이그레이션, 운영 데이터, 외부 설정은 코드 revert만으로 복구되지 않을 수 있으므로 해당 작업의 복구 절차를 따로 확인한다.
