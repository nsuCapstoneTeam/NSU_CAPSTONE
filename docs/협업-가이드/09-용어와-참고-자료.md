## 자주 쓰는 용어

| 용어 | 이 가이드에서의 의미 |
|---|---|
| commit | 선택한 변경과 이유를 로컬 이력에 기록 |
| push | 로컬 커밋을 원격 저장소에 올림 |
| fetch | 현재 작업 브랜치에 통합하지 않고 원격 정보 수신 |
| pull | 원격 정보를 받은 뒤 현재 브랜치에 통합 |
| fast-forward | 갈라진 이력을 합치지 않고 브랜치를 앞으로 이동 |
| merge | 두 개발 이력을 통합 |
| rebase | 커밋을 다른 기준 위에 다시 적용해 이력을 재구성 |
| PR | 변경을 검토하고 기준 브랜치에 반영하도록 요청 |
| Squash Merge | PR 변경을 한 커밋으로 합쳐 기준 브랜치에 반영 |
| CI | 코드 변경 시 자동 실행하는 빌드·테스트 등의 검증 |
| Advisory | 검토에 참고하되 필수 병합 조건으로 강제하지 않는 의견 |
| CodeRabbit Review | GitHub PR에서 자동으로 수행하는 AI 1차 코드 리뷰 |
| Learning | CodeRabbit이 리뷰 대화에서 학습해 향후 리뷰에 적용하는 팀/Repository별 선호 정보 |
| Path Instruction | 특정 파일 경로에만 적용하는 CodeRabbit 리뷰 지침 |
| Source of Truth | 같은 정보가 여러 곳에 있을 때 최종 판단 기준이 되는 공식 원본. 요구사항은 GitHub `docs/`가 담당 |
| Two-way Sync | Linear와 GitHub Issues 중 한쪽의 변경을 다른 쪽에도 반영하는 양방향 동기화 |
| Acceptance Criteria | 동기화된 Linear / GitHub Issue가 완료되었다고 판단하기 위한 구체적인 완료 조건 |
| Human Review 3종 체크 | Requirement/Issue, Code 구현, Documentation 영향을 사람이 함께 확인하는 최종 리뷰 기준 |
| Root Message 태그 | Slack 논의 영역을 표시하는 `[FRONT]`, `[BACK]`, `[COMMON]` 태그 |
| Human Confirm | 팀 논의 후 사람이 확정한 요구사항·정책. Agent의 문서 변경 기준 |
| `ToDo` | 확정 문서를 기준으로 이슈가 생성된 Linear 상태 |
| `In Progress` | 연결된 일반 PR이 열려 실제 구현을 리뷰 중인 Linear 상태 |
| `Done` | 연결된 PR이 `main`에 Squash Merge되어 완료된 Linear 상태 |
| magic word | 커밋·PR에서 이슈 키 앞에 붙여 이슈 상태를 바꾸는 예약어 |
| revert | 기존 커밋의 변경을 취소하는 새 커밋 생성 |
