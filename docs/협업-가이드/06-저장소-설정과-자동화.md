# 저장소 설정과 자동화

← [가이드 목차](README.md)

## 공지와 자동화의 역할

**운영 문서로 기준을 남기고, Slack에는 문서 링크와 적용 방법을 알리며, 저장소가 강제할 수 있는 규칙은 GitHub 설정으로 적용한다.**

| 규칙 | 적용 위치 | 도입 방법 |
|---|---|---|
| 브랜치·커밋·PR 작성 방식 | 문서, PR 템플릿, 사람 리뷰 | 가이드와 예시 공유 |
| 커밋 템플릿 등록 | 각 팀원의 clone | 초기 설정 실행 및 결과 확인 |
| `main` 직접 push 방지 | GitHub Ruleset | PR 필수 설정과 우회 권한 확인 |
| 사람 승인 1명 이상 | GitHub Ruleset + 팀 리뷰 | 승인 수 설정, 실제 사람 승인 확인 |
| 빌드·테스트 기준 | GitHub Actions + Required Check | 워크플로 검증 후 필수화 |
| Squash Merge | GitHub 저장소 설정 | Squash만 병합 방식으로 허용 |
| 작업 브랜치 정리 | GitHub + 각 팀원 PC | 원격 자동 삭제, 로컬 별도 정리 |
| AI PR 리뷰 | CodeRabbit Review | 초기 Advisory로 운영 |

GitHub의 CI나 서버 설정은 팀원 PC의 로컬 Git 설정을 통제하지 않는다. 로컬 설정은 사용자가 바꿀 수 있고 clone만으로 공유되지 않는다.

## 현재 저장소 상태 — 2026-09-14 확인

대상 저장소는 `nsuCapstoneTeam/NSU_CAPSTONE` Organization 소유의 공개 저장소다.

| 항목 | 현재 상태 |
|---|---|
| 기본 브랜치 | `main` |
| ChatGPT GitHub App | Organization에 설치, `NSU_CAPSTONE` 선택 접근 |
| Squash Merge | ON |
| Merge Commit | OFF |
| Rebase Merge | OFF |
| Auto Merge | OFF |
| Merge 후 head branch 자동 삭제 | ON |
| CodeRabbit Organization 등록 | 완료 |
| CodeRabbit Slack 연결 | 연결되어 있으나 공식 개발 Workflow의 필수 단계로 사용하지 않음 |
| CodeRabbit PR 자동 리뷰 | 새 PR에서 재검증 필요 |
| Linear ↔ CodeRabbit 직접 연동 | 공식 Workflow에서 사용하지 않음 |
| GitHub Actions CI | 실제 FE/BE 구조 생성 후 구성 |
| `main` Ruleset | CI 검증 후 적용 |
| 팀원 Organization 초대 | 전체 자동화/보호 설정 검증 후 진행 예정 |

Merge 방식은 현재 팀 합의와 일치한다. `main` 보호는 CI의 실제 check 이름을 확인한 뒤 Ruleset으로 적용한다.

## 저장소 관리자의 설정 체크리스트

### 병합 방식

`Settings → General → Pull Requests`에서 다음 값을 유지한다.

- [x] `Allow squash merging` ON
- [x] `Allow merge commits` OFF
- [x] `Allow rebase merging` OFF
- [x] 병합 후 작업 브랜치 자동 삭제 ON
- [x] Auto Merge는 초기 운영에서 OFF
- [ ] Squash 기본 메시지 형식은 팀이 첫 실제 기능 PR에서 최종 확인

최종 병합은 사람이 수행하고, Squash 커밋 메시지를 팀 커밋 규칙에 맞게 검토한다.

### ChatGPT GitHub App

Organization의 GitHub App 권한은 최소 범위로 유지한다.

```text
nsuCapstoneTeam
└── ChatGPT GitHub App
    └── Repository access: Only select repositories
        └── NSU_CAPSTONE
```

새 저장소를 만들었다고 자동으로 접근 범위를 넓히지 않는다. 필요할 때만 Organization 관리자가 별도로 추가한다.

## CodeRabbit 도입 및 검증 순서

상세 설정은 [10. CodeRabbit PR Review](10-coderabbit-pr-review.md)를 따른다.

초기 원칙:

1. CodeRabbit GitHub App은 `NSU_CAPSTONE`에만 접근하도록 제한한다.
2. Organization을 CodeRabbit Dashboard에 등록한다.
3. Review Profile은 처음에는 `chill`을 사용해 중요한 버그·보안·정확성 이슈 위주로 확인한다.
4. Auto Review는 ON, incremental review는 ON, Draft PR 자동 리뷰는 OFF로 시작한다.
5. `request_changes_workflow`는 OFF로 두어 CodeRabbit을 Advisory Reviewer로 유지한다.
6. PR Summary는 ON으로 사용한다.
7. Path Instructions는 FE/BE 코드가 실제로 들어온 뒤 필요한 규칙만 추가한다.
8. 새 테스트 PR에서 자동 리뷰가 실제로 동작하는지 검증한다.
9. 리뷰 품질과 노이즈를 몇 개 PR에서 확인한 뒤 `.coderabbit.yaml` 도입 여부를 결정한다.
10. 초기에는 CodeRabbit 자체를 GitHub Ruleset의 Required Check로 등록하지 않는다.

### CodeRabbit Slack 연결

Slack 연동 자체는 유지할 수 있지만 **공식 개발 Workflow의 필수 단계로 사용하지 않는다.** 팀의 기본 흐름은 GitHub PR에서 동작하는 CodeRabbit Review만을 기준으로 한다.

Slack `@CodeRabbit`을 개인적인 보조 조사에 사용할 수는 있지만 그 결과는 Source of Truth가 아니며, 팀의 필수 절차·승인 조건·문서 동기화 수단으로 취급하지 않는다.

### Linear와 CodeRabbit의 관계

Linear는 확정된 작업과 Acceptance Criteria의 Source of Truth다. CodeRabbit과 Linear를 직접 연결하지 않아도 된다.

Human Reviewer가 PR에서 다음을 직접 비교한다.

```text
Linear Issue / Acceptance Criteria
        ↕
실제 코드와 테스트
        ↕
README / docs/ / ADR 영향
```

따라서 이 팀의 공식 Workflow에서는 CodeRabbit Linear Integration이나 Knowledge Base 연결을 필수 설정으로 두지 않는다.

## GitHub Actions CI 등록 순서

CI는 저장소의 **실제 구현 구조와 실행 명령**을 확인한 뒤 만든다. 현재 `backend/`, `frontend/`는 디렉터리만 존재하므로 프레임워크/빌드 파일이 들어오기 전에 명령을 가정해서 workflow를 만들지 않는다.

구현 코드가 들어온 뒤 다음 순서로 진행한다.

1. Backend의 실제 Java/Gradle 버전과 테스트·빌드 명령을 확인한다.
2. Frontend의 실제 Node/package manager와 lint/test/build 명령을 확인한다.
3. `.github/workflows/`에 PR 검증 workflow를 추가한다.
4. 샘플 PR에서 정상 변경의 성공과 의도적 오류의 실패를 모두 확인한다.
5. GitHub에 표시된 실제 check 이름을 기록한다.
6. 문서-only, Frontend-only, Backend-only PR에서도 Required Check가 영원히 Pending 상태로 남지 않는지 확인한다.
7. 검증이 끝난 check만 `main` Ruleset의 Required Status Check로 등록한다.

경로 필터로 workflow 전체가 실행되지 않으면 Required Check가 대기 상태에 남을 수 있다. 따라서 Ruleset을 먼저 만들고 CI 이름을 추측해서 넣지 않는다.

## 마지막 단계: `main` Ruleset

CodeRabbit과 CI를 실제 PR에서 검증한 뒤 `Settings → Rules → Rulesets`에서 `main` 대상 Branch Ruleset을 만든다.

권장 최종값:

| 설정 | 값 |
|---|---|
| Pull Request 없이 변경 | 금지 |
| Required approvals | 작성자 외 사람 1명 이상 |
| Dismiss stale approvals | ON 권장 |
| Require conversation resolution | ON |
| Required status checks | 검증된 CI check만 등록 |
| Require branch up to date | CI 운영 방식 확인 후 활성화 |
| Force push | 금지 |
| `main` 삭제 | 금지 |
| Require linear history | ON |
| Bypass | 일상 작업에서는 사용하지 않도록 최소화 |
| CodeRabbit | 초기에는 Required Check 아님 |

Ruleset 적용 후 작은 실제 PR을 하나 만들어 **PR 생성 → CI → CodeRabbit → Human Review 3종 체크 → Squash Merge → 브랜치 자동 삭제** 전체 흐름을 검증한다. 모든 자동화와 보호 설정이 정상 동작한 뒤 팀원을 Organization에 초대한다.
