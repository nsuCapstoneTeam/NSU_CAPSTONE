# ADR: 행사 소프트 삭제

- 상태: **Proposed** (PR 리뷰에서 확정)
- 결정일: **2026-10-18** (NSU-54·58 설계 세션)
- 관련: [03 행사 API §5.5·§5.6](../../api/03_events.md), [02 추천 응답 §5.2](../../api/02_recommendation_trust_and_new_artist.md), 서버 협의 014 결정 2, SSOT `EVT-041`, NSU-54

---

## Decision

행사 삭제는 행을 지우지 않고 삭제 시각을 남기는 소프트 삭제다.

- 삭제한 행사는 모든 API에서 `404 EVENT_NOT_FOUND`다. 등록자도 같다.
- 그 행사로 만든 추천 결과는 지우지 않는다.
- 삭제와 취소를 구분한다. 취소한 행사는 `CANCELLED`로 남아 보이고, 삭제한 행사는 목록과 조회에서 사라진다. 둘 다 되돌릴 수 없다.
- 지금은 시작 전후, `OPEN`·`CANCELLED`와 관계없이 삭제할 수 있다. Offer가 생기면 Offer가 있는 행사는 삭제를 막고 취소만 허용한다.

## Context

`EVT-041`은 EVENT_PARTNER의 기능으로 "Event 삭제/취소"를 둔다. 지금 프런트는 한 번 확인한 뒤 행사를 바로 지우며, 되돌릴 수 없다.

추천 생성 횟수(같은 행사 1분 간격, 사용자당 하루 5회)는 저장된 추천 결과의 요청자와 생성 시각으로 센다(02 §5.2, 서버 협의 014 결정 2). 제한은 AI 호출 비용과, 추천 결과로 받을 수 있는 원본 재생 주소의 반복 수집을 막기 위한 것이다.

앞으로 Offer(`BOOKING-058`), DM(`DM-060`, Event 또는 Offer와 연결), 공연 결과 원장이 행사를 가리키게 된다. 지금은 이 가운데 아무것도 구현되지 않았다.

## Rationale

행사를 지울 때 추천 결과도 함께 지우면, 다음 순서를 반복해 하루 5회 제한을 피할 수 있다.

```text
행사 등록 → 추천 5회 → 행사 삭제(결과도 삭제, 센 횟수 0) → 다시 등록 → …
```

네 방식을 비교했다.

| 방식 | 횟수 제한 | 나중의 참조(Offer·DM·원장) | 사용자 경험 |
|---|---|---|---|
| 소프트 삭제 | 지킨다 | 깨지지 않는다 | 삭제가 늘 된다 |
| 하드 삭제 + 결과도 삭제 | 피할 수 있다 | 다시 설계해야 한다 | 삭제가 늘 된다 |
| 하드 삭제 + 결과의 행사 참조만 끊음 | 하루 5회는 지키고, 같은 행사 1분 간격은 뜻을 잃는다 | 다시 막아야 한다 | 삭제가 늘 된다 |
| 추천을 받은 행사는 삭제 불가(취소만) | 지킨다 | 추천 외의 참조는 다시 막아야 한다 | 왜 삭제가 안 되는지 헷갈린다 |

소프트 삭제만 횟수 제한과 나중의 참조를 모두 지키고, 삭제 가능 여부가 이력에 따라 달라지지 않는다.

## Consequences

- 모든 행사 조회에 삭제 여부 조건이 붙는다. 목록 인덱스는 삭제하지 않은 행만 담는다(`WHERE deleted_at IS NULL`).
- 삭제한 행사가 DB에 남는다. 보관 기간과 완전 삭제, EVENT_PARTNER가 탈퇴할 때 행사를 어떻게 처리할지는 정하지 않았다. 행사 설명 같은 자유 입력에 개인정보가 들어갈 수 있으므로 보관 정책이 필요하다.
- 사용자에게는 삭제가 영구 삭제처럼 보인다. 복구 기능은 두지 않는다.
- 삭제해도 추천 결과는 남아 생성 횟수 계산에 들어간다.
- 추천을 만드는 동안 행사를 삭제해도 결과는 저장해 횟수에 넣고, 응답은 `404`다(03 §8.4). 저장 직전에 다시 검사해 결과를 버리면 생성 중 삭제로 제한을 피할 수 있기 때문이다.

## Rejected Alternatives

- **하드 삭제 + 결과도 삭제**: 가장 단순하지만, 삭제로 하루 5회 제한을 피할 수 있어 서버 협의 014 결정 2와 충돌한다.
- **하드 삭제 + 결과의 행사 참조만 끊음**: 행사 데이터는 실제로 사라지지만, 추천 결과 테이블이 행사 없는 행을 다뤄야 하고 Offer 등이 생기면 하드 삭제를 다시 막아야 한다.
- **추천을 받은 행사는 삭제 불가**: 횟수 제한은 지키지만, 상태가 아닌 이력에 따라 삭제 가능 여부가 달라져 사용자가 헷갈린다.
