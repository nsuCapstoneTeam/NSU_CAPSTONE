# 009. 종합 적합도의 항목 구성

## Status

Accepted — 2026-10-05 #ai-recommend AI 협의 6/9에서 AI 담당이 제안하고 Backend(김동엽)가 합의. 메인 SSOT 반영 전.
점수가 빠진 항목의 처리, BPM·리듬 정규화 수식, 공연 형태의 비교 규칙은 미정이다.

## Context

메인 SSOT는 종합 적합도를 항목 점수(0~100)의 평균으로 정하고(`AI-MATCH-053`), 항목으로 음악 의미·스타일, BPM, 리듬, 공연 스타일을 들었다(`AI-MATCH-052`·`054`).
공연 스타일 점수를 누가 어떻게 계산할지는 어디에도 정해져 있지 않았다.
음악의 분위기·스타일은 이미 의미 점수(요청 문장과 곡의 CLAP 유사도)에 반영된다.

## Decision

종합 적합도에 들어가는 항목은 **3개**다. 세 항목 모두 AI가 계산한다.

| 항목 | 값 | 내용 |
|---|---|---|
| 의미 | `SEMANTIC` | 요청한 분위기·스타일 문장과 곡이 얼마나 비슷한지. 음악 분위기·스타일은 여기에 포함한다 |
| BPM | `BPM` | 요청 템포와 곡의 BPM이 얼마나 맞는지 |
| 리듬 | `RHYTHM` | 요청 리듬과 곡의 리듬이 얼마나 맞는지 |

- **공연 스타일 점수는 따로 두지 않는다.** 분위기·스타일을 의미 점수와 공연 스타일 점수에 두 번 반영하지 않기 위해서다.
- **밴드·솔로·DJ 같은 공연 형태**는 Backend가 아티스트 프로필과 행사 요청을 비교한다. 행사에 반드시 필요한 조건이면 PASS/FAIL 필터로 처리한다.
- 정의가 없는 항목(예: "아티스트 적합도")은 평균에 넣지 않는다.
- 세 항목의 평균으로 종합 적합도를 계산하는 일은 Backend Ranker가 한다([005](005-audio-retrieval-responsibilities.md)).

## Rationale

같은 음악 특징을 두 항목에 나눠 넣으면 그 특징이 종합 점수에 두 배로 반영된다.
공연 형태는 음악 분석이 아니라 프로필 정보라 Backend가 가진 데이터로 판단할 수 있다.

## Consequences

메인 SSOT `AI-MATCH-052`·`054`의 "공연 스타일 적합도"와 `AI-MATCH-051`의 필수 조건 목록을 고쳐야 한다.
공연 형태가 필터가 되면 추천 응답의 통과 조건 목록(`passedConditions`)에 값이 추가된다. enum 값 추가라 기존 클라이언트를 깨지 않는다.

## Server Responsibilities

- AI: 의미·BPM·리듬 점수 계산과 0~100 정규화.
- Backend: 세 항목의 평균으로 종합 적합도 계산, 공연 형태 비교·필터.

## Contract

AI는 곡마다 세 항목 점수를 준다. 아직 정하지 않은 것:

- 점수가 빠진 항목(예: BPM 추출 실패)을 평균에서 빼는지, 0점으로 넣는지, 최소 몇 개 항목이 있어야 추천하는지(AI 제안: 빠진 점수는 `null`과 사유로 구분)
- BPM·리듬 점수의 정규화 수식과 기준값
- 공연 형태의 프로필 필드·분류·비교 규칙, 그리고 필터로 쓰는 기준
