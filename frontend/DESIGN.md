# 할래말래 Design System

> 이 문서는 [VoltAgent/awesome-design-md](https://github.com/VoltAgent/awesome-design-md)(MIT)의 DESIGN.md 형식을 따라 **할래말래 프런트엔드 화면 규칙**을 정리한 것입니다.
> AI 코딩 도구(Claude 등)나 팀원이 새 화면을 만들 때 이 파일을 먼저 읽으면, 지금 화면과 같은 색·글꼴·모양으로 만들 수 있습니다.
> 10장은 [Leonxlnx/taste-skill](https://github.com/Leonxlnx/taste-skill)(MIT)의 "Anti-Slop" 규칙 중 우리 프로젝트에 맞는 것만 골라 적용한 것입니다. 1~9장과 10장이 다르면 **10장이 우선**입니다.
> 11장은 [ui-ux-pro-max](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill)(MIT)의 사용성·접근성 점검 규칙입니다. 모양은 1~10장, 쓰기 편함과 접근성은 11장으로 점검합니다.
> 값은 `src/app.css`와 `src/features/auth/components/*.css`의 실제 코드 기준입니다. 코드가 바뀌면 이 문서도 같이 고쳐 주세요.

## 1. Visual Theme & Atmosphere

할래말래는 **음악과 무대를 서로에게 맞게 연결하는** 아티스트-행사 매칭 서비스입니다. 화면의 기본은 밝고 깨끗한 **흰 바탕 + 파란색(`#0866df`)** 입니다. 이 조합은 확정 로고와 남서울대학교의 파랑·흰색에서 왔습니다(Linear NSU-25).

정보 화면(매칭 결과, 게시판, 마이페이지, 회원가입)은 **읽기 쉬움이 먼저**입니다. 점수·추천 이유·입력칸은 장식 없이 또렷하게 보여 줍니다. 반대로 **로그인 화면은 공연장의 분위기**를 보여 줍니다. 어두운 콘서트 사진이 천천히 바뀌는 배경, 계속 도는 CD, 레코드판 같은 원형 로그인 창이 있습니다.

모양의 특징은 **원과 알약**입니다. CD, 원형 로그인 창, 간편 로그인 버튼은 완전한 원(50%)입니다. 로그인 입력칸, 선택 버튼, 태그 칩은 알약(999px)입니다. 일반 카드와 버튼은 부드러운 모서리(10-15px)입니다.

**핵심 특징**
- 흰 바탕 + 할래말래 블루(`#0866df`) 하나를 주 색으로 사용
- 역할마다 색을 나눔: **아티스트 = 파랑**, **행사 관계자 = 코랄**
- 글꼴은 Noto Sans KR 하나만 사용, 제목은 굵고 자간이 좁음
- 원·알약 모양으로 음악(CD·레코드)을 연상시킴
- 라이트·다크 모드를 모두 지원 (CSS 변수만 바꿔서 전환)
- 움직임은 CSS만 사용, **움직임 줄이기 설정을 항상 존중**
- 기능이 아직 연결되지 않은 곳은 "체험용", "연결 준비 중"이라고 솔직하게 표시

- **성공**: `--green`

### 그림자
- **기본 카드**: `--shadow` (`0 15px 55px #163e7a0a`, 아주 옅음)
- **떠 있는 안내 카드**: `0 18px 40px rgba(20, 40, 64, 0.18)`
- **사진 위 원형 로그인 창**: `0 24px 60px rgba(0, 0, 0, 0.35)` + 흰 링

## 3. Typography Rules

### 글꼴
- **Noto Sans KR** (Google Fonts, 400-900) 하나만 사용합니다. 다른 글꼴을 추가하지 마세요.
- 한글 제목은 `word-break: keep-all`로 단어 중간에서 줄이 바뀌지 않게 합니다.

### 크기 단계

| 역할 | 크기 | 굵기 | 자간 | 예 |
| --- | --- | --- | --- | --- |
| 히어로 제목 | `clamp(35px, 4vw, 53px)` | 900 | -2.5px | 홈 첫 화면 |
| 페이지 제목 | 34px | 기본 | -1.5px | 화면 상단 제목 |
| 로그인·가입 제목 | 22-28px | 기본 | -1px | "아티스트 로그인" |
| 섹션 제목 (h2) | 25px | 기본 | -0.8px | |
| 카드 제목 (h3) | 18-20px | 기본 | | |
| 본문 | 13-14px | 400 | | 줄 간격 1.8 |
| 라벨·버튼 | 13-14px | 600-700 | | |
| 보조·안내 | 11-12px | 400-600 | | 입력칸 아래 안내 |
| Eyebrow | 9-10px | 800 | 2px | `FOR ARTISTS`, 영문 대문자, `--blue` |
| 태그 | 10px | 600 | | |

### 원칙
- **Eyebrow는 화면 맨 위에 한 번만** 씁니다(작은 파란 영문 대문자 → 큰 한글 제목). 화면 안의 섹션마다 반복하지 않습니다. (10.6)
- 본문은 작고(12-14px) 줄 간격은 넉넉하게(1.8) 둡니다.
- 버튼과 안내 문구는 **친근한 반말형 서비스 말투**를 씁니다: "가입할래!", "처음이신가요?", "CD를 눌러 바꿔 보세요".

## 4. Component Stylings

### 버튼
**Primary (주요 버튼)**
- 바탕 `--blue`, 글자 `--on-blue`, 14px / 700
- 여백 15px 22px, 모서리 10px (로그인·가입처럼 원형 화면 안에서는 **알약 999px**)
- 호버: 2px 떠오르고 파란 그림자, 누르면 `scale(0.98)`
- 로딩: `aria-busy="true"` + 버튼 문구 바꾸기("로그인 중…"). 버튼 안의 짧은 대기에만 작은 회전 표시를 허용하고, 화면 내용을 불러올 때는 스켈레톤을 씁니다. (10.4)

**Secondary**
- 바탕 `--surface`, 테두리 1px `--line`, 글자 `--ink`, 모서리 10px
- 호버: 테두리가 `--blue`로

**Text button**
- 바탕 없음, 글자 `--blue`, 13px (예: "← 홈으로 돌아가기")

**원형 아이콘 버튼 (간편 로그인)**
- 지름 40-64px, 50% 모서리. 카카오 `#fee500`, 네이버 `#03c75a`, 구글 흰 바탕 + `#4285f4`
- 호버: 4px 떠오름, 누르면 `scale(0.94)`

### 입력칸
- 일반 입력칸: 모서리 7px, 테두리 `--line`, 포커스 시 테두리 `--blue` + 4px 옅은 파란 빛
- 로그인 입력칸: **알약(999px)**, 글자 가운데 정렬, **떠오르는 라벨**(`.login-float`): 비어 있으면 라벨이 칸 가운데, 누르거나 입력하면 테두리 위로 올라가 12px로 남고 칸에는 형식 안내(placeholder)가 보임
- 로그인 배경 사진은 오른쪽 위 **배경 멈춤/재생** 버튼으로 멈출 수 있음 (역할을 바꿔도 멈춤 상태 유지)
- 행사 관계자 인증번호: 가입 화면과 같은 60초 타이머, "00:59 후 재전송 → 인증번호 재전송", 만료되면 인증번호 칸 잠김
- 오류: `aria-invalid="true"` → 테두리 `#c93643` + 옅은 붉은 빛
- 비밀번호 칸에는 항상 **보기/숨기기 버튼**(눈 아이콘)을 둠

### 선택 버튼 (알약)
- 하나만 고르기(radio) / 여러 개(checkbox) 모두 알약 모양
- 기본: 테두리 `--line`, 글자 `--muted` / 선택: 바탕 `--tint`, 테두리·글자 `--blue`
- 실제 입력칸은 숨기되 키보드와 화면 낭독기로 쓸 수 있게 유지

### 카드·패널
- 바탕 `--surface`, 테두리 1px `--line`, 모서리 15px, 여백 26px, 그림자 `--shadow`
- 안내 상자: 바탕 `--soft`, 모서리 14px

### 로그인 화면 전용
- **CD** (`role-cd`): 지름 `clamp(560px, 50vw, 760px)`, 화면 왼쪽 밖으로 30% 걸침
  - 무지개빛 `conic-gradient` + 트랙 홈 `repeating-radial-gradient`, 가운데 역할 색 라벨
  - 평소 한 바퀴 20초로 회전, 누르면 0.65초 동안 빨라지며 역할 전환
  - 반사광은 돌지 않음, 바깥 흰 선 4px
- **역할 표시 칸**: CD 링 위 반투명 유리 카드(`backdrop-filter: blur(10px)`), 위아래 2칸 하이라이트
- **원형 로그인 창** (`login-circle`): 지름 `clamp(400px, 34vw, 500px)`, 흰 테두리 2px + 반투명 링 10px + 흰 선 3px
- **배경** (`login-slideshow`): `src/assets/login-bg/`의 사진을 5초 보여 주고 1.5초 동안 전환, 어두운 막 + 역할 색
- 로그인 화면에서는 상단 메뉴와 체험판 안내 줄을 숨김

### 회원가입 화면 (`sign-up-design.css`, 아티스트·행사 관계자 가입 공통)
- 제목 위에 로그인 CD와 이어지는 **작은 CD**(72px, 20초에 한 바퀴)
- `.signup-page--designed` 안에서만 적용. 역할 색은 `--role-a`/`--role-b`/`--role-text` 변수: 아티스트 파랑, 행사 관계자 코랄(`#ff8a5b` → `#e8505b`, 글자는 `#c4364a`로 대비 5.3:1)
- 역할 색은 CD 라벨·카드 위 띠·단계 번호·진행 표시·제목 위 영문에만 쓰고, 선택 버튼·포커스 테두리 같은 조작 요소는 브랜드 파랑을 유지
- 폼 카드: 모서리 28px, 맨 위 역할 색 띠 5px, 위쪽 배경에 옅은 역할 색 빛
- 입력칸·선택 상자·버튼 모두 **알약(999px)**. 섹션 머리는 번호(01~04) 대신 내용 이름으로 구분 (10.6, 정리 예정)
- 인증 카드는 인증이 끝나면 초록 테두리·바탕으로 바뀜
- 4단계 진행 표시, 완료 단계는 ✓
  - 아티스트: 로그인 정보 → 본인 확인 → 아티스트 정보 → 약관 동의
  - 행사 관계자: 담당자 정보 → 연락처 인증 → 주최 정보(선택) → 약관 동의
- 공통 부품은 `features/auth/components/signup-fields.jsx` (인증 칸, 알약 선택, 진행 표시, 빠진 항목 카드)
- **필수·선택 표시**: 필수 항목은 라벨 옆 빨간 `*`(`LabelText required`, 묶음은 `ChoiceGroup required`), 표시가 없으면 선택. 폼 맨 위 오른쪽에 "* 표시는 필수 항목이에요." 안내. 약관 동의는 `[필수]` 글자를 그대로 씀
- 아티스트 연락 수단(이메일, 전화·문자, 인스타그램 DM)은 고른 것만 연락처 입력칸이 열리고, 열린 칸은 필수. 이메일·전화는 인증한 값이 미리 채워짐
- 인증 카드: 바탕 `--soft`, 모서리 14px, 버튼 문구는 "인증번호 요청 → 00:59 후 재전송 → 인증 완료"로 바뀜
- 빠진 항목은 가입 버튼을 누른 뒤에만 오른쪽 아래 떠 있는 카드로 안내하고, 누르면 그 칸으로 이동 + 잠깐 붉게 반짝임

## 5. Layout Principles

### 간격
- 기본 단위는 4px 배수에 가깝게 씁니다: 8 · 12 · 16 · 18 · 24 · 32px
- 화면 좌우 여백 32px, 콘텐츠 최대 폭 1176px (`.page-container`는 1240px + 좌우 32px)

### 배치
- 일반 화면: 가운데 정렬 한 단 (회원가입 화면 최대 폭 760px)
- 로그인 화면: 2단 (왼쪽 CD, 오른쪽 원형 로그인 창은 오른쪽 칸 가운데)

### 모서리 단계

| 이름 | 값 | 쓰는 곳 |
| --- | --- | --- |
| 작게 | 5-7px | 태그, 일반 입력칸 |
| 기본 | 9-10px | 버튼, 인증 버튼 |
| 카드 | 14-15px | 카드, 안내 상자, 인증 카드 |
| 크게 | 20-24px | 큰 패널, 역할 표시 칸 |
| 알약 | 999px | 로그인 입력칸, 선택 버튼, 칩, 로그인 버튼 |
| 원 | 50% | CD, 원형 로그인 창, 간편 로그인, 아이콘 버튼 |

## 6. Depth & Elevation

| 단계 | 처리 | 쓰는 곳 |
| --- | --- | --- |
| 0 바탕 | `--bg` | 페이지 |
| 1 면 | `--surface` + `--line` 테두리 | 카드, 패널, 입력칸 |
| 2 카드 | `--shadow` (아주 옅음) | 패널, 로그인·가입 카드 |
| 3 떠 있음 | `0 18px 40px rgba(20,40,64,.18)` | 빠진 항목 안내, 알림 |
| 4 사진 위 | 흰 링 + `0 24px 60px rgba(0,0,0,.35)` | 원형 로그인 창, CD |

**원칙**: 흰 화면에서는 그림자를 아주 옅게, 어두운 사진 위에서는 흰 테두리로 또렷하게 띄웁니다.

## 7. Do's and Don'ts

### Do
- 색은 항상 `--blue`, `--ink`, `--line` 같은 **CSS 변수**로 쓰기
- 역할을 보여 줄 때는 **아티스트 파랑 / 행사 관계자 코랄**을 지키기
- 새 애니메이션에는 반드시 `@media (prefers-reduced-motion: reduce)`로 끄는 코드 넣기
- 오류는 **해당 칸 표시(`aria-invalid`) + 그 칸으로 이동**으로 알려 주기
- 연결 안 된 기능은 "체험용", "연결 준비 중"이라고 쓰기
- 라이트·다크 모드 **둘 다** 확인하기
- 파일 이름은 kebab-case, 기능별로 `src/features/<기능>/` 아래에 두기 (`src/code-guide.md`)

### Don't
- 다른 글꼴이나 새 주 색을 추가하지 않기
- CLAP·AI가 연결되기 전에 "AI 분석 중" 같은 오해할 문구 쓰지 않기 (NSU-25)
- 아티스트 실력을 점수로 평가하는 표현 쓰지 않기 ("노래 실력 68점" 등, AI-040)
- 출연료를 행사 관계자가 아닌 사용자에게 보여 주지 않기 (ART-028)
- 비공개 정보를 **화면에서만 숨기는 것**으로 끝내지 않기. 백엔드 권한 검사가 필요 (SEC-100)
- 무거운 라이브러리(Three.js 등)를 가볍게 추가하지 않기. CSS로 먼저 해결
- 출처를 모르는 사진·이미지 쓰지 않기 (`src/assets/login-bg/CREDITS.md` 참고)

## 10. Taste 규칙 (Anti-Slop)

AI가 만든 화면에서 자주 보이는 "티 나는 기본값"을 피하기 위한 규칙입니다. taste-skill 원문은 Tailwind, Motion, Next.js를 전제로 하지만 우리 프로젝트는 **React + Vite + 일반 CSS**이므로, 같은 뜻을 우리 방식으로 옮겼습니다.

### 10.1 적용 범위
- **꼭 적용**: 홈, 로그인처럼 서비스 첫인상을 보여 주는 화면
- **기본 규칙만 적용**: 회원가입, 매칭, 게시판, 마이페이지처럼 입력·데이터 중심 화면. 원문도 여러 단계 폼과 대시보드는 범위 밖이라고 밝히므로 10.4~10.8(상태, 폼, 금지 패턴, 접근성)만 지킵니다.

### 10.2 시작 전에: Design Read와 다이얼
새 화면을 만들기 전에 한 줄로 방향을 적습니다.
> 예: "아티스트 회원가입 화면을 처음 가입하는 아티스트에게, 할래말래 파랑의 친근한 말투로, 기존 로그인 디자인(원·알약)을 이어서 만든다."

화면 성격에 따라 세 다이얼을 정합니다. (1 = 낮음, 10 = 높음)

| 화면 | 변화(VARIANCE) | 움직임(MOTION) | 밀도(DENSITY) |
| --- | --- | --- | --- |
| 홈·로그인 (브랜드 화면) | 6 | 5 | 3 |
| 회원가입·마이페이지 (입력 화면) | 3 | 3 | 4 |
| 매칭 결과·게시판 (정보 화면) | 3 | 2 | 5 |

- 움직임 4 이상: 실제로 움직여야 함(등장, 반응). 3 이하: 마우스 올림·누름 반응만.
- 다이얼을 바꾸려면 이 표를 고치고 팀에 공유합니다.

### 10.3 색·글자·모양 잠금
- **강조 색은 할래말래 파랑 하나.** 행사 관계자 코랄은 "역할 표시"에만 쓰는 의미 색입니다. 다른 장식 색을 추가하지 않습니다.
- **보라색 AI 그라데이션, 네온 빛 번짐 금지.** 그림자는 바탕색에 맞춘 옅은 그림자만 씁니다. 큰 제목에 그라데이션 글자를 쓰지 않습니다.
- **모양 잠금**: 4장의 모서리 규칙(입력·버튼은 알약, 카드는 14~15px, CD·원형 창은 50%)을 화면 전체에 똑같이 적용합니다. 한 화면 안에서 네모 버튼과 알약 버튼을 섞지 않습니다.
- **카드는 계층을 보여 줄 때만** 씁니다. 단순히 묶기만 할 때는 여백이나 구분선으로 충분합니다.
- **화면 테마 잠금**: 한 화면은 라이트 또는 다크 하나. 섹션마다 테마를 뒤집지 않습니다. (로그인 화면의 사진 배경은 화면 전체가 하나의 장면이므로 예외)
- 글꼴은 한글 지원 때문에 Noto Sans KR을 유지합니다. 강조는 같은 글꼴의 굵기로 하고, 다른 글꼴(특히 세리프)을 섞지 않습니다.

### 10.4 상태와 피드백
- 모든 화면에 **로딩·빈 상태·오류** 세 가지를 만듭니다. "성공한 화면"만 만들지 않습니다.
- 내용을 불러올 때는 **스켈레톤**(최종 모양과 같은 회색 틀), 버튼을 누른 뒤 짧은 대기는 버튼 문구 변경(+작은 회전 표시)으로 알립니다.
- 오류는 **입력칸 바로 아래**에 표시하고, 화면 아래 알림(toast)은 잠깐 지나가는 안내에만 씁니다.
- 누르면 `scale(0.98)` 또는 1px 내려가는 반응을 줍니다.
- **버튼·폼 대비 검사**: 버튼 글자, 입력칸 글자, 안내 글자, 오류 글자가 모두 WCAG AA(본문 4.5:1, 18px 이상 3:1)를 넘어야 합니다. 사진 위 버튼은 반드시 바탕이나 테두리를 둡니다.
- **버튼 문구는 한 줄**, 주요 버튼은 3단어 이내. 같은 의도의 버튼은 한 화면에서 같은 문구를 씁니다(예: "가입할래!"와 "회원가입하기"를 섞지 않기).

### 10.5 폼 규칙
- **라벨은 입력칸 위**, 안내 문구도 위 또는 아래에 항상 있고, 오류는 아래.
- **placeholder를 라벨 대신 쓰지 않습니다.** placeholder는 입력 예시("예: 서울·경기")만.
- 빠진 항목은 가입 버튼을 누른 뒤에 알려 주고, 그 칸으로 이동시킵니다. (회원가입 화면 방식)

### 10.6 움직임
- **움직임에는 이유가 있어야 합니다**: 계층(어디를 볼지), 이야기(순서대로 보여 주기), 피드백(눌렀음을 알림), 상태 변화(바뀌었음을 알림). "멋있어서"는 이유가 아닙니다.
- `transform`과 `opacity`만 움직입니다. `top`, `left`, `width`, `height`를 애니메이션하지 않습니다.
- **계속 반복되는 움직임은 화면당 최소한으로.** 로그인 화면의 CD 회전과 배경 사진 전환처럼 브랜드 장면을 만드는 것만 허용합니다.
- 모든 움직임은 `@media (prefers-reduced-motion: reduce)`에서 멈춥니다.
- `window.addEventListener('scroll', ...)`은 쓰지 않습니다. 스크롤 효과가 필요하면 `IntersectionObserver`나 CSS 스크롤 애니메이션을 씁니다.

### 10.7 금지 패턴 (AI 티)
- **긴 대시(—)와 범위용 대시(–) 금지.** 화면에 보이는 글자에서는 일반 하이픈(-), 쉼표, 마침표, 괄호를 씁니다. 시간 범위도 `12:00-23:00`.
- **이모지 금지**(🎤, 📋 등). 아이콘이 필요하면 아이콘 라이브러리를 씁니다. ✓ 같은 기호도 아이콘으로 바꾸는 것을 권장합니다.
- **손으로 그린 SVG 아이콘·장식 금지.** 아이콘은 하나의 라이브러리만 씁니다(권장: Phosphor `@phosphor-icons/react`). 설치 전 `package.json`을 확인하고 팀과 정합니다. 단, CD처럼 단순한 원 모양 장식은 CSS로 그리는 것을 허용합니다.
- **의미 없는 장식 점 금지**(예: 체험판 안내 줄 앞의 파란 점). 실제 상태를 나타낼 때만 씁니다.
- **가운뎃점(·) 남용 금지.** "서울·경기", "결제·정산"처럼 한국어 단어를 나열하는 표준 용법은 괜찮지만, `A · B · C · D`처럼 정보 띠를 가운뎃점으로 이어 붙이지 않습니다. 한 줄에 최대 1개.
- **섹션 번호 라벨 금지**("01", "02" 배지, "Step 1/2/3"). 단계는 내용 이름("로그인 정보", "본인 확인")으로 보여 줍니다.
- 스크롤 안내("↓ 스크롤"), 버전 라벨("v0.6", "BETA"), 사진 위에 얹은 태그, 꾸밈용 사진 출처 문구를 쓰지 않습니다. (사진 출처는 `CREDITS.md`에)
- **문구 점검**: 어색하거나 뜻이 모호한 문구, AI가 쓴 듯한 멋 부린 문장, 근거 없는 정밀 숫자(예: "만족도 98.7%")를 쓰지 않습니다. 샘플 숫자는 "샘플"이라고 표시합니다.
- "혁신적인", "차세대", "원활한" 같은 빈 수식어 대신 구체적인 동사를 씁니다.
- 같은 모양의 카드 3개를 가로로 나란히 두는 배치를 기본으로 쓰지 않습니다.

### 10.8 다크 모드·성능·접근성
- 라이트·다크 모드를 **처음부터 함께** 만들고, 기본값은 사용자의 시스템 설정(`prefers-color-scheme`)을 따르는 것을 목표로 합니다.
- 순수 검정(`#000`)은 쓰지 않습니다. 순수 흰색(`#fff`) 바탕은 현재 브랜드 기본값이라 유지하되, 새 화면에서 큰 흰 면이 겹칠 때는 `--soft`로 단계를 줍니다.
- 글꼴은 장기적으로 Google Fonts 링크 대신 프로젝트 안에 넣어(`@font-face` + `font-display: swap`) 불러옵니다.
- z-index는 단계표만 씁니다: 배경 장식 `-1~-2`, 화면 안 겹침 `1~2`, 떠 있는 안내 `50`, 본문 바로가기 `100`.
- 성능 목표: LCP 2.5초 미만, INP 200ms 미만, CLS 0.1 미만. 큰 이미지는 압축(WebP), 무거운 라이브러리는 필요한 화면에서만 불러옵니다.

### 10.9 출시 전 점검표
작업이 끝나면 하나씩 확인합니다. 하나라도 아니면 완료가 아닙니다.
- [ ] Design Read 한 줄과 다이얼 값을 정했다
- [ ] 화면에 보이는 글자에 `—`, `–`가 하나도 없다
- [ ] 이모지, 손으로 그린 아이콘, 의미 없는 장식 점이 없다
- [ ] 강조 색은 파랑 하나(+역할 코랄), 모서리 규칙이 화면 전체에서 같다
- [ ] eyebrow는 화면 맨 위 한 번, 섹션 번호 라벨이 없다
- [ ] 버튼 문구가 한 줄이고, 같은 의도의 버튼 문구가 같다
- [ ] 라벨이 입력칸 위에 있고, placeholder를 라벨로 쓰지 않았다

## 11. UI/UX Pro Max 점검 규칙 (사용성·접근성)

[nextlevelbuilder/ui-ux-pro-max-skill](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill)(MIT)의 UX 규칙 중 우리 웹 화면에 맞는 것만 골랐습니다. 스킬 원본은 `.claude/skills/ui-ux-pro-max/`에 설치되어 있습니다.

### 11.1 역할 나누기
- **모양(색·글꼴·모서리·분위기)은 1~10장이 정합니다.** 이 스킬이 추천하는 디자인 시스템(어두운 OLED 테마, 보라·초록 팔레트, Poppins·Righteous 글꼴)은 쓰지 않습니다. 확정 로고 색(NSU-25)과 맞지 않고, 두 글꼴은 한글이 없습니다.
- **11장은 "쓰기 편한가, 모두가 쓸 수 있는가"를 점검하는 기준**입니다. 10장(taste)과 겹치면 더 엄격한 쪽을 따릅니다.
- 앱(iOS·Android) 전용 규칙(안전 영역, 햅틱, 하단 탭 등)은 지금 계획에 없으므로 뺐습니다.

### 11.2 점검 순서 (중요한 것부터)
| 순서 | 분야 | 꼭 지킬 것 |
| --- | --- | --- |
| 1 | 접근성 | 글자 대비 4.5:1 이상, 키보드로 모두 조작, 포커스 테두리 보이기, 아이콘만 있는 버튼에 이름(`aria-label`), 움직임 줄이기 설정 지키기 |
| 2 | 누르기·반응 | 누르는 영역 최소 44×44px(웹 최소 24×24px), 버튼 사이 8px 이상, 처리 중에는 버튼 잠금 + 진행 표시, 마우스 올리기에만 의존하지 않기 |
| 3 | 성능 | 사진은 WebP/AVIF, 크기 미리 잡아 화면 밀림 막기, 아래쪽 이미지는 늦게 불러오기 |
| 4 | 스타일 일관성 | 모든 화면 같은 스타일, 이모지를 아이콘으로 쓰지 않기, 화면마다 주요 버튼 1개 |
| 5 | 배치·반응형 | 가로 스크롤 없음, 확대 막지 않기, 375 / 768 / 1024 / 1440px에서 확인 |
| 6 | 글자·색 | 본문 16px 기준, 줄 간격 1.5 이상, **12px보다 작은 글자 쓰지 않기**, 색만으로 의미 전달하지 않기(아이콘·글자 같이) |
| 7 | 움직임 | `transform`·`opacity`만 움직이기, 한 화면에 핵심 움직임 1~2개, 사라질 때는 나타날 때보다 짧게, 움직이는 중에도 조작 가능 |
| 8 | 폼 | 보이는 라벨, 오류는 해당 칸 바로 아래 + `aria-describedby`, 오류 문구는 "원인 + 고치는 법", 알맞은 `type`/`inputMode`/`autoComplete` |
| 9 | 이동 | 뒤로 가기가 예상대로 동작, 현재 위치 표시, 화면 바뀌면 본문으로 포커스 이동 |
| 10 | 차트·데이터 | 매칭 점수: 색만으로 구분하지 않기, 숫자도 같이 보여 주기 |

### 11.3 우리 화면에 바로 쓰는 규칙
- **자동으로 바뀌는 콘텐츠에는 멈춤 수단을 둡니다.** 로그인 배경 슬라이드쇼처럼 계속 바뀌는 것은 멈춤 버튼을 두거나, 포커스·움직임 줄이기 설정에서 멈춥니다.
- **인증번호 칸은 `autoComplete="one-time-code"`** 를 씁니다. 문자로 온 번호를 자동으로 채울 수 있습니다.
- **비밀번호 칸은 붙여넣기와 비밀번호 관리자를 막지 않습니다.**
- **가입 실패 시**: 빠진 항목 요약을 보여 주고, 각 항목을 누르면 해당 칸으로 이동합니다. 칸 아래 오류 문구도 그대로 둡니다.
- **처리 결과 알림**은 포커스를 빼앗지 않고 `aria-live="polite"`로 읽어 줍니다.
